## 1. Executive Summary

ALOE (Architecture-Typed, Multi-Objective LoRA Optimisation for Local Agentic Small Language Models) v0.1.0-alpha establishes a formal, reproducible, and automated pipeline for fine-tuning Small Language Models (<3B parameters) on agentic tool-use tasks. 

Prior Parameter-Efficient Fine-Tuning (PEFT) frameworks operate under three fundamental blind spots:
1. **Architecture Blindness (Gap 1):** Uniform rank and alpha allocation across all linear projections, treating sliding-window attention, full softmax attention, state-space models (Mamba-2), and feed-forward networks identically.
2. **Optimization Rigidity (Gap 2):** Widespread reliance on the rigid $\alpha = 2r$ heuristic, ignoring layer-specific gradient propagation and learning-rate scaling dynamics.
3. **Execution & Kernel Blindness (Gap 3):** Silent failure when attaching adapters to layers that bypass autograd paths (e.g., custom Mamba-2 CUDA/MPS kernels), burning search compute on inert parameters.

ALOE v0.1.0-alpha resolves all three gaps:
- It autonomously inspects neural topologies, classifies module groups by architectural role, and enforces provable gradient reachability (`Validity.VALID` vs. `Validity.EXCLUDED`).
- It emits backend-agnostic `SearchGrammar` specifications without manual intervention or per-model heuristics.
- It provides a rigorous pre-flight gradient verification trap (`verify_gradients()`) that rejects inert configurations before executing training steps.
- It profiles resource consumption using true 100ms sampled process Resident Set Size (RSS) under Apple Silicon unified memory.

With v0.1.0-alpha, **Gates A, B, and C are fully verified and closed**, backed by 74 passing unit tests and six empirical pilot runs across Gemma 4-E2B and Falcon-H1 1.5B.

## 2. Frozen Core Architecture & Data Contracts

ALOE v0.1.0-alpha establishes strict architectural decoupling between inspection, grammar generation, execution, and optimization. All interfaces are validated via Pydantic schemas.

```
┌────────────────────────────────────────────────────────────────────────┐
│ Stage 1: INVENTORY (architecture/inspector.py)                         │
│ Walks nn.Module tree -> ArchitectureDescription (Backend-Agnostic)      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│ Stage 2: CLASSIFY (architecture/typing.py + adapters/)                 │
│ Assigns ComponentType (LOCAL_ATTN, GLOBAL_ATTN, SSM, FFN, etc.)        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│ Stage 3: CONSTRAIN & VALIDATE (architecture/constraints.py)            │
│ (Architecture x Backend) -> VALID | VALID_WITH_SPECIAL | EXCLUDED      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│ Stage 4: EMIT GRAMMAR (search_space/grammar.py)                        │
│ Emits SearchGrammar (Pure Pydantic Data Contract, Zero Framework Dep)  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ ◄── [FROZEN CONTRACT BOUNDARY]
┌───────────────────────────────────▼────────────────────────────────────┐
│ Stage 5: EXECUTION (execution/backends/peft_mps.py)                    │

└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Core Schema Specifications

1. **`ArchitectureDescription` & `ModuleRecord` (`aloe/architecture/schema.py`)**
   - Pure, backend-agnostic inventory of model layers.
   - `ComponentType`: Strongly typed enum containing `LOCAL_ATTENTION`, `GLOBAL_ATTENTION`, `LINEAR_ATTENTION`, `SSM`, `FFN`, `ROUTER`, `EXPERT`, `EMBEDDING`, `NORM`, and `OTHER`.
   - `Validity`: `VALID` (gradient verified), `VALID_WITH_SPECIAL_HANDLER`, `UNSUPPORTED`, and `EXCLUDED` (provably inert or kernel-bypassed).
   - Enforces the invariant that no module is labeled `VALID` simply because an adapter attaches; it must physically receive backpropagated gradients.

2. **`ModelMetadata` & `ModelAcquisitionRecord` (`aloe/datasets/model_registry.py`)**
   - Version 1.0 JSON acquisition envelope providing immutable SHA-256 hashes, file manifests, parameter precision (`bf16`), local snapshot paths, and tokenizer chat templates.
   - `ModelRegistry`: High-level lookup supporting aliases (`gemma`, `model_a`, `falcon-h1`, `model_b`) with path resolution and offline caching under `runs/models/`.

3. **`SearchGrammar` & `GroupDimensions` (`aloe/search_space/schema.py`)**
   - Derived automatically from `ArchitectureDescription`. Never handwritten.
   - Defines orthogonal search dimensions per adaptable component group:
     - `enabled`: `[True, False]`
     - `rank`: `[4, 8, 16, 32]`
     - `alpha`: `[8, 16, 32, 64, 128]` (enables decoupling from the $2r$ heuristic, directly addressing Gap 2)
   - Carries an explicit `excluded: dict[str, str]` dictionary mapping excluded parameter names to architectural justifications.
   - Fully serializable to JSON; contains zero PyTorch, PEFT, or MLX types.

4. **`TrialConfig` (`aloe/execution/trial_config.py`)**
   - Represents a concrete point in the search space.
   - Contains `trial_id`, `model_id`, `backend`, `dataset_manifest_path`, `seed`, `group_settings` (map of group names to `GroupTrialSetting`), and `training` (`TrainingParameters`).
   - `validate_against_grammar()`: Programmatically rejects configs targeting excluded modules or invalid groups.
   - `to_peft_lora_config()`: Converts trial settings into HuggingFace PEFT `LoraConfig` with heterogeneous `rank_pattern` and `alpha_pattern` dictionaries.

5. **`BaseExecutionBackend` & `PeftMPSBackend` (`aloe/execution/backends/`)**
   - Standardized backend interface with mandatory `verify_gradients()` and `run_trial()` lifecycle hooks.
   - `PeftMPSBackend`: Manages training on Apple Silicon MPS (`torch.bfloat16`), background process RSS telemetry, and fresh subprocess reload testing.

## 3. Evidence of Completed Verification Gates

### 3.1 Gate A: Data Pipeline & End-to-End Smoke Training
- **Condition:** Tool-disjoint dataset split verified, model loads, LoRA trains on the split, adapter saves, reloads in a fresh process, and `aloe inspect` emits a typed JSON map.
- **Verification Evidence:**
  - **Tool-Disjoint Manifest (`aloe/data/manifests/xlam_pilot_v1.json`):** 800 training examples and 200 validation examples partitioned from Salesforce xLAM function-calling dataset.
  - Verified disjointness invariant: $\text{TrainTools} \cap \text{ValTools} = \emptyset$ (0 intersecting tools across 1,000 total samples).
  - Manifest cryptographic integrity verified by `tests/test_xlam_split.py`.
  - Smoke training executed on `google/gemma-4-E2B-it`: adapter weights saved to disk and successfully re-instantiated in a fresh Python subprocess (`aloe/runs/probe/`).

### 3.2 Gate B: Automated Grammar Differentiation
- **Condition:** `aloe inspect` on `google/gemma-4-E2B-it` and `tiiuae/Falcon-H1-1.5B-Instruct` produces structurally and mathematically distinct search grammars from the identical codebase without manual overrides.
- **Verification Evidence (`aloe/runs/grammars/DIFFERENTIATION_REPORT.md`):**
  - **Gemma 4-E2B:** Emitted 3 component groups (`local_attention`, `global_attention`, `ffn`).
    - Discovered partial K/V projection topology: layers 0–14 have 4 targets (`q, k, v, o`), whereas layers 15–34 have 2 targets (`q, o`).
    - Local vs. Global target count: 80 local attention targets vs. 20 global attention targets (exact 4:1 sliding window ratio).
  - **Gemma 4-E4B:** Emitted 110 local attention targets vs. 22 global attention targets (exact 5:1 sliding window ratio), verifying autonomous adaptation to intra-family architectural shifts.
  - **Falcon-H1 1.5B:** Emitted 3 component groups (`global_attention`, `ssm`, `ffn`). Zero local attention targets.
    - Discovered 24 SSM state-space targets (`in_proj`, `x_proj`) running parallel to attention.
    - Autonomously excluded all 24 `model.layers.<N>.mamba.conv1d` modules with documented justification: autograd kernel bypass.
  - Differentiation asserted in continuous integration via `tests/test_differentiation.py`.

### 3.3 Gate C: Pre-Flight Execution Trap & Clean Memory Profiling
- **Condition:** Full execution chain operational end-to-end on two architectures, with dynamic pre-train gradient verification and true process RSS memory tracking.
- **Verification Evidence (`aloe/runs/trials/gate_c_verification_trial/trial.json`):**
  - **Pre-Flight Gradient Verification Trap:** Implemented in `PeftMPSBackend.verify_gradients()`. Before running any trial, a synthetic forward-backward step inspects all adapter parameters. If any parameter exhibits zero gradient norm, it is flagged as `GRADIENT_MISSING`, and the trial aborts immediately (`INVALID_CONFIG`).
  - **Negative Control Verification:** An intentional trial targeting Falcon-H1's `mamba.conv1d` was trapped and aborted before training, with all 48 adapter tensors identified as `GRADIENT_MISSING` (`tests/test_invalid_config_aborts.py`, `scripts/verify_gradients.py`). Compute waste prevented: 100%.
  - **Clean Process RSS Memory Tracking:** Enforced per ADR-004. Evaluated at 100ms sampling intervals via `aloe/evaluation/resources.py`, capturing true unified memory footprint (`process_rss_unified`) rather than the misleading `mps_driver_allocated_gb` diagnostic.

## 4. Empirical Pilot Execution Summaries

ALOE v0.1.0-alpha was exercised across six empirical pilot runs on an Apple Silicon M1 Max workstation (64 GB Unified Memory), evaluating three configurations per model family.

> **Statistical Validity Notice:** Consistent with FYP research ethics and rigorous benchmarking standards, these $N=1$ pilot runs verify pipeline reproducibility, gradient flow, and memory instrumentation. They are not claimed as generalizable proof of architectural superiority over baseline LoRA.

### 4.1 Hardware Latency Asymmetry & ADR-012

Mamba-2 SSM chunk scanning on Apple Silicon MPS currently falls back to reference PyTorch operations, creating a ~10× step latency asymmetry:
- **Gemma 4-E2B:** **713 ms/step**
- **Falcon-H1 1.5B:** **6,918 ms/step**

To prevent single-model search campaigns from monopolizing workstation compute, **ADR-012** established an asymmetric search budget:
- Gemma 4-E2B: 25 steps per pilot trial (configured for 200 steps in full search).
- Falcon-H1 1.5B: 12 steps per pilot trial, sequence length 256 (configured for 75 steps in full search).

### 4.2 Empirical Pilot Results

#### Gemma 4-E2B (`google/gemma-4-E2B-it`)

| Config | Architecture Strategy | Tool Accuracy | Peak RSS (GB) | Train Time | Trainable Params | Pareto Status |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |

*Key finding:* Config P2 achieved identical accuracy (62.5%) with **16.7% fewer trainable parameters** (10.06M vs. 12.08M) than uniform LoRA, establishing parameter-efficiency viability for subsequent Bayesian optimization.

## 6. Architectural Decisions Record (ADR) Index

| ADR | Title | Core Decision & Rule |
| :--- | :--- | :--- |
| **ADR-001** | Architecture-typed search space | Search over typed architectural groups, not uniform $r$ or heuristic ranking. |
| **ADR-002** | Search grammar as clean data contract | Grammar must contain zero backend types (pure Pydantic/JSON). |
| **ADR-003** | MoE 4-bit expert-skipping handling | Explicitly isolate router vs. expert layers; document 4-bit limitations. |
| **ADR-004** | Process RSS as primary memory metric | Measure sampled process RSS at 100ms; driver allocation is diagnostic only. |
| **ADR-005** | xLAM tool-disjoint evaluation split | Enforce $\text{TrainTools} \cap \text{ValTools} = \emptyset$ with SHA-256 integrity checks. |
| **ADR-006** | Pre-flight gradient verification trap | Every backend must implement `verify_gradients()`; inert layers are `EXCLUDED`. |
| **ADR-007** | Automated grammar differentiation | `aloe inspect` must differentiate model grammars without modifying core engine. |
| **ADR-013** | Multi-fidelity Bayesian optimization | SAAS-GP surrogate with qLogNEHVI acquisition function for October Gate D. |
| **ADR-014** | Paired bootstrap statistical protocol | Paired bootstrap across $\ge 3$ seeds; report 95% CIs and p-values for Gate E. |
| **ADR-010** | PEFT on MPS primary execution backend | PEFT on Apple Silicon MPS is primary; MLX reserved for uniform baselines. |
| **ADR-011** | BFloat16 precision on Apple Silicon | Default to `bfloat16`; 4-bit NF4 is marked unsupported on Apple Silicon MPS. |
| **ADR-012** | Cloud GPU hardware tier for Mamba-2 hybrid acceleration | Two-tier execution: Apple Silicon MPS primary; GCP L4 Spot offload for Falcon-H1 CUDA-accelerated SSM trials. |
